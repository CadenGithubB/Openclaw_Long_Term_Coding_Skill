# Animation evidence for Android tasks

Read this when an Android acceptance contract includes moving graphics, transitions,
collision behavior, disappearing objects, freezes or rendering performance.
Use the existing parent-owned acceptance contract and restricted controller. This
extension grants no host shell, generic ADB, arbitrary device selection or deployment.

This is prepared guidance, not installed recording or vision support. Confirm a real
enrolled capture backend, protected durable lifecycle and permitted analysis worker
before requesting these operations. Fake-backend success does not satisfy this gate.
If a capability is unavailable, record the missing setup and continue independent
checks; do not invent a tool, invoke a host shell or claim animation was tested.

Retain the build/APK digest, renderer, expected visual behavior and exact owned
emulator registration before a test. Select a controller-issued target handle;
the controller resolves serial, ADB-server identity, emulator process incarnation,
guest boot identity, display geometry and ownership. Reject reused/stale targets.

Ask the admitted controller for a short recording with a bounded timed sequence of
tap/swipe/allowlisted key inputs. Initial candidate bounds are 15 seconds and 32
actions, one active recorder, 32 MiB capture bytes. The request supplies no command,
host path, device serial, endpoint or arbitrary key/text string. Controller-owned
profiles preserve orientation/aspect ratio. Record requested offsets and observed
monotonic dispatch/ack intervals; those are not app-consumption times or media PTS.

Retrieve the operation's manifest and admitted bytes after exact recorder stop is
confirmed. Preserve failed/partial recordings and cancellation uncertainty. Run
media decoding in the existing authorized restricted Linux analysis environment
with network disabled, bounded memory/CPU/output and prepared read-only tools.
An OS-name check is not evidence of confinement. Never execute the APK/build scripts
on macOS. Review fixed host-controller helpers separately.

Start with at most four timestamped images. Ask for at most eight images from a
specific source-time interval when an event needs closer inspection. Preserve raw
media PTS, time base, source frame index and selection requests. Do not regenerate
timestamps as index/fps or equate tick resolution with capture/display uncertainty.
Keep cumulative frame/byte/action budgets in the existing protected controller;
worker-editable files or directory counts cannot enforce durable admission.

The model must receive actual verified image bytes through a supported local image
message. A filename, video path, contact-sheet path or text description is not image
delivery. The candidate builds native Ollama image JSON only. Identify the actual
active route before drawing a transport conclusion: the saved Stage 4J controller
rejects `images` and caps requests at 256 KiB; the separately tested Stage 4AC native
route declares image input and passes raw requests through a 4 MiB local proxy,
but that test did not verify image-byte delivery or model consumption. Neither
record establishes working vision. Keep the route's stricter existing limits;
the candidate's proposed larger image/request budget does not raise them.

Preserve admission, model digest, locality, abort and cumulative budgets when
reviewing image support. A loopback endpoint can still serve a cloud-backed model:
require the pinned local weights, reject remote-model metadata and retain the
local-only execution restrictions. Never substitute a cloud model or fallback.
Until the exact route passes a pixel-only nonce challenge, image-byte/hash receipt,
ordering reversal and text-only control, record delivery as unverified. Score Qwen
defect-detection accuracy separately. Direct MP4 stays disabled unless its own
exact-stack byte-delivery probe succeeds.

Visual findings cite specific frames/time intervals and expected behavior. Inspect
direction, disappearance, transitions, collisions and possible freezes. Sparse
samples cannot exclude brief flicker/dropped frames; all decoded frames still omit
anything the recorder missed. Repetition can reflect a static scene or capture stall.
Separate capture failure, insufficient coverage and application defects. A fixture
pixel oracle is not a general app checker or Qwen inference.

Performance needs applicable rendering/presentation timestamps. Determine whether
the app uses ordinary View/Canvas, SurfaceView Canvas, OpenGL or Vulkan. Do not apply
View metrics or assumed FrameTimeline coverage to unsupported surfaces. Video PTS
and “looks smooth” do not establish frame pacing. Retain raw trace/source/layer
identity, measured refresh interval, capture-on/off controls and emulator settings.
Emulator measurements describe this environment; physical-device claims need their
own measurements.

Return structured capture, visual, performance and model-path statuses separately.
Map evidence into the existing acceptance.py levels only after parent review.
Pipeline success cannot automatically satisfy behavior/visual criteria. Pending
model, real capture or profiler tests stay pending. Cancellation intent is recorded
before cleanup; unresolved recorder activity prevents another recording.
